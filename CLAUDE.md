# 9. 3D PERFORMANCE RULES

Any 3D implementation MUST:

* use lazy loading when appropriate;
* avoid blocking initial rendering;
* use GPU-friendly geometry;
* avoid excessive polygon counts;
* limit draw calls;
* use instancing when useful;
* respect device capabilities;
* support mobile fallback;
* support reduced motion;
* avoid unnecessary continuous rendering;
* pause animation when offscreen.

Use:

```text
IntersectionObserver
```

or equivalent visibility detection when appropriate.

If WebGL is unavailable:

Provide an elegant static fallback.

The fallback must still look intentional.

---

# 10. MOBILE 3D

On mobile:

* simplify geometry;
* reduce particles;
* reduce animation;
* reduce camera movement;
* potentially replace 3D with a 2D analytical visual.

The mobile experience must remain premium.

# 11. MOTION DESIGN SYSTEM

Motion must have hierarchy.

### Level 1 — Ambient

Very subtle.

Examples:

* background movement;
* data flow;
* atmospheric depth.

### Level 2 — Structural

Used when entering sections.

Examples:

* reveal;
* stagger;
* section transitions;
* chart appearance.

### Level 3 — Interactive

Triggered by user actions.

Examples:

* hover;
* pointer movement;
* button interactions;
* card transitions.

### Level 4 — Cinematic

Reserved for:

* Hero;
* major transitions;
* important Case Study moments.

Do not use cinematic motion everywhere.

# 30. CLIENT / SERVER BOUNDARIES


* React;
* TypeScript;
* Tailwind CSS;
* next-intl;
* Three.js;
* React Three Fiber;
* Drei;

> **Approved does not mean mandatory.**
